# 宽泛条目黑名单（约束 ③ 的兜底，不是主力）。
#
# 主力是 refine-candidates.py 的**统称检测**：一个中文名被 ≥2 个物种共用就自动判为统称，
# 不需要人来枚举。实测它一次就抓出 26 个渔业统称（沙条 18 种、鲂仔 20 种、大沙 12 种），
# 这类词不可能靠手写名单穷举。
#
# 这张表只收统称检测抓不到的那一类：**在本池子里只有一个物种叫这个名字，但它其实是
# 科/目级的统称**。所以下面每一行都是高阶类元名，不是任何单一物种的正名。
#
# 三条硬规则（改这张表前必读，理由见 SPEC.md §5.3）：
#   1. 全串精确匹配，不做子串。子串匹配下「老虎」会连带干掉「东北虎」「孟加拉虎」。
#   2. 不收单字词（虎、熊、狼）。单字词几乎必然是别的正名的子串。
#   3. 不能用「字数 ≤2」当判据。薮猫、蜜獾、棕熊、豹猫、兔狲都是 2 字的具体物种。
#
# 要豁免某一行，把它加进 whitelist.txt，不要在这里删 —— 删掉就没人知道曾经拦过它。
#
# SPEC §5.3 的初始名单里有一批**单字词**（虎 熊 狼 豹 鹿 猴 猿 鹰 隼 雕 鸮 鹤 鲸 龟
# 蛇 蛙 虾），这里一个都没收。不是漏了：匹配是全串相等，而中文名闸门要求 ≥2 字
# （lib.ZH_RE），单字名根本进不到这一步 —— 收进来纯粹是死条目，还会让人误以为
# 这张表在做子串匹配。

# —— 用户点名的统称 ——

# 按「多物种共用」的标准统称检测永远抓不到它们。收在这里的理由是约束 ③ 直接点了名：
# 「不是一类动物的宽泛介绍（老虎、狮子）」。
#
# 用户同时把「美洲狮」列为正例，而它也是物种级 —— 所以这条约束**不是按分类阶元划的，
